Third-party files used by the embroidery digitizer's "find the person in a photo" step
======================================================================================

selfie_multiclass_256x256.tflite
  Google MediaPipe "selfie multiclass" image-segmentation model (256 x 256 input; classes:
  background, hair, body skin, face skin, clothes, others).
  Source:  https://storage.googleapis.com/mediapipe-models/image_segmenter/selfie_multiclass_256x256/float32/latest/selfie_multiclass_256x256.tflite
  Licence: Apache License, Version 2.0 - https://www.apache.org/licenses/LICENSE-2.0
  The model card says it is not meant for decisions that put lives at risk or where a pixel-perfect mask
  is needed, and that surveillance and identity recognition are out of scope. Here it only decides which
  colours a stitched picture gets. It runs in the visitor's browser; no picture is uploaded.

wasm/vision_wasm_internal.js and wasm/vision_wasm_internal.wasm
  The WebAssembly runtime of @mediapipe/tasks-vision (version 1.2.2), copied unchanged from the npm package
  (node_modules/@mediapipe/tasks-vision/wasm). This is the classic-worker flavour: Next's bundler runs the
  digitizer's worker as a classic worker (see lib/digitizer/segment.worker.js).
  Source:  https://www.npmjs.com/package/@mediapipe/tasks-vision
  Licence: Apache License, Version 2.0 - https://www.apache.org/licenses/LICENSE-2.0
  Copyright Google LLC.
  To update: install the new version of the package, copy the two files again, and keep the package version
  in package.json the same as the one these files came from (the JavaScript and the wasm must match).
